# How `prove-it` works

The starter has eight source files and one independent gate. The file map shows
what each file does and where the small starter stops.

The exemplar run follows the real provider path behind `demo-compare.sh`. It
shows one goal, one fixed Done Contract and the gate loop used in class.

Each course session studies one slice of this process. The sessions do not use
six separate systems.

<div id="sourceExplorer" class="source-explorer"><p>The interactive source guide needs JavaScript. You can still read the source in this order: loop, provider, tools, events, runview, contract, root and probe.</p></div>

The gate also proves one narrow fact. The named checks passed for one pinned
candidate. The receipt does not prove that the checks were strong enough.

It also assumes that the worker cannot replace the gate or read its key. Read
[Can the worker tamper with the gate key?](CONTAINMENT.md) for the missing
security boundary and the production version of the pattern.
